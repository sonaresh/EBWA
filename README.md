# EBWA — Evidence-Bound Workload Authorization

**Closing the Attestation-to-Authorization Gap: Evidence-Bound Workload Authorization for Enterprise Multi-Cloud Platforms**

EBWA is a provider-neutral authorization model that binds workload identity to the exact executing artifact, verified software provenance, applicable policy, and freshness-bounded runtime posture at protected runtime authorization.

## Research artifact

This repository is the reproducibility home for the EBWA manuscript and prototype.

### Validated results

- 16/16 automated tests passed.
- 20 security/failure scenarios under full EBWA (D) passed; 100 A–E configuration-scenario records were generated.
- 10,000 logical workload identities were evaluated in fresh, cached-high-reuse, and cached-large-working-set profiles.
- Full EBWA maintained EBAR = 1.0.
- Fresh 10k p95: baseline A 1.947 ms; full EBWA D 3.224 ms.
- High-reuse cache: D p95 2.444 ms with 95.4% cache hit rate.
- 200 drift events: p95 revocation delay 6.316 ms.
- Two independent kind clusters: 11/11 expected security assertions passed.
- Amazon EKS external validation: 11/11 expected security assertions passed.
- AWS server-side authorization p95: 1.317 ms (ebwa-east) and 1.234 ms (ebwa-west).

- `SHA256SUMS.txt` — integrity hashes for the public artifacts
- `MANIFEST.md` — artifact inventory and exclusions

## Data availability

The evidence in this repository is original research data generated by the EBWA reference implementation. The public package contains the final local benchmark archive, two-cluster kind evidence, AWS EKS evidence, a sanitized v1.4.0 prototype, result summaries, and SHA-256 integrity hashes. Generated private keys, runtime secrets, local databases, temporary credentials, and kubeconfig material are intentionally excluded.
